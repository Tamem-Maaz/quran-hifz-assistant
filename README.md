# المساعد بحفظ القرآن الكريم

مساعد شخصي للحفظ يقود جلسة حفظ يومية متكاملة، ويجدول مراجعة المحفوظ سابقًا تلقائيًا
(السبقي والمنزل). لا يعرض التطبيق نص الآيات أو التفسير — فقط مرجع المقطع؛ التلاوة
والتفسير من مصادرك المعتادة.

**التطبيق مباشر على:** https://tamem-maaz.github.io/quran-hifz-assistant/

راجع [`docs/PROJECT_PLAN.md`](docs/PROJECT_PLAN.md) للخطة المعمارية الكاملة (النطاق،
القرارات، نموذج البيانات، مراحل التنفيذ). هذا الملف يوثّق حالة التنفيذ الفعلية.

## الحالة

كل مراحل الخطة السبع (القسم 18) منجزة:

| المرحلة | المخرجات |
|---|---|
| 1. الأساس | نموذج البيانات، `storage/`، الترحيل، التحقق، CI |
| 2. الرحلة الأساسية | المراحل الست، الاستئناف، التوجيه، لوحة اليوم |
| 3. حماية البيانات | تصدير/استيراد متحقَّق، إعادة ضبط، تذكير النسخ الاحتياطي |
| 4. المساعد الحقيقي | جدولة المراجعة (السبقي/المنزل)، سجل الأخطاء |
| 5. التحفيز | الإحصائيات، التتابع، الهدف، الختم المتوقع، الخرائط الذهنية |
| 6. دون إنترنت | Service Worker حقيقي، إدارة تحديث، يعمل كاملًا بلا اتصال |
| 7. الصقل | تدقيق وصولية AA آلي (axe-core)، ميزانية الأداء، توثيق |

## التقنية

JavaScript خام + ES Modules بلا أداة بناء، `localStorage` خلف واجهة مجرّدة، وJSDoc
للتحقق من الأنواع عبر TypeScript (`--checkJs`). لا خادم خلفي ولا أسرار — بيانات
المستخدم تبقى بالكامل في متصفحه ولا تغادره إطلاقًا.

## التشغيل محليًا

```bash
npx serve .
```

الافتتاح على أي منفذ ثابت (مثل `http://localhost:5173`) — التطبيق وحدات ES تعمل
عبر HTTP، ولن تعمل بفتح `index.html` مباشرة من نظام الملفات.

## الأوامر

```bash
npm test              # اختبارات الوحدة (Vitest) — core/ وstorage/
npm run test:coverage # الاختبارات مع تقرير التغطية (≥ 90% لـ core وstorage)
npm run lint          # ESLint (يمنع innerHTML)
npm run typecheck     # tsc --noEmit --checkJs
npm run e2e           # Playwright: تدفقات حرجة، وصولية، وميزانية الأداء
```

## هيكل المشروع

- `src/core/` — منطق النطاق الخالص (دوال بلا DOM ولا تخزين ولا `Date.now()` مباشر).
- `src/storage/` — طبقة التخزين خلف واجهة `repository.js` المجرّدة.
- `src/ui/` — التوجيه (`router.js`)، المخزن (`store.js`)، المكوّنات، والشاشات
  (اليوم، جلسة جديدة، جلسة الحفظ، المراجعة، الإحصائيات، الخرائط، الإعدادات).
- `src/ui/styles/` — نظام التصميم بطبقات ذرّية (انظر القسم التالي).
- `src/data/` — بيانات ثابتة: `surahs.json` (114 سورة)، `maps.json` (فهرس الخرائط
  الذهنية المتوفرة من `docs/maps/`).
- `service-worker.js` — cache-first للأصول، network-first لمستند التطبيق، إدارة
  تحديث بلافتة داخل التطبيق.

قاعدة صارمة: `src/core/` لا يستورد من `src/ui/` ولا `src/storage/` إطلاقًا.

## نظام التصميم

الهوية مأخوذة من صفحة المصحف نفسها: ورقٌ مُصفرّ خفيفًا سطحًا، وحبرٌ دافئ نصًّا،
واللازورد (أزرق المخطوطات) لونًا للتفاعل وحده، والذهب للزخرفة والعلامة فقط،
والشنجرف للخطر والخطأ لا غير. خطّان: **Reem Kufi** للعناوين (كوفي مستوحى من
عناوين السور المزخرفة) و**IBM Plex Sans Arabic** للنصّ والواجهة؛ الأرقام تعود
تلقائيًا إلى الثاني فتتجاور الأشكال الهندسية مع الكوفي الهندسي.

العنصر المميّز هو **علامة الربع** (النجمة الثمانية المفرَّغة) بثلاثة أدوار
وظيفية لا زخرفية: شعار التطبيق، ودالّ الصفحة الحالية في هامش التنقّل، وحصى
عدّاد التكرار — كل تكرار مُنجَز يطبع علامةً ذهبية، فيُقرأ ما تبقّى بلمحة كما
تُعدّ الأرباع في هامش المصحف.

الملفات في `src/ui/styles/` خمس طبقات ذرّية، ترتيبها معلَن بـ `@layer` فلا
يعتمد على ترتيب الوسوم في `index.html`:

| الطبقة | الملف | المحتوى |
|---|---|---|
| 0. الرموز | `tokens.css` | الخطوط، والألوان الخام، والطبقة الدلالية (`--bg`, `--fg`, `--accent`)، والسمتان |
| 1. الأساس | `base.css` | التصفير وعناصر HTML العارية — بلا أصناف إطلاقًا |
| 2. الذرّات | `atoms.css` | زرّ، حقل، تسمية، شارة، علامة ربع، خطّ فاصل |
| 3. الجزيئات | `molecules.css` | بطاقة، صفّ، عدّاد، بلاطة إحصائية، صفّ أزرار، نافذة تأكيد |
| 4. الأعضاء | `organisms.css` | الهامش والعمود الرئيسي، خريطة النشاط، المعرض، نقاط التوقّف |

تبديل السمة يعيد ربط الطبقة الدلالية وحدها؛ لا مكوّن يشير إلى لون خام مباشرة.

## الاختبارات

- **`tests/core/` و`tests/storage/`** (Vitest): دوال خالصة، تغطية ≥ 90%.
- **`tests/e2e/`** (Playwright، تُشغَّل عبر `npm run e2e`):
  - `memorization-journey.spec.js` — رحلة سبق كاملة، وجدولة السبقي/المنزل عند
    النجاح والإخفاق، بما فيها تحقّق فعلي (`page.clock`) من ظهور مقطع مستحق
    للمراجعة بعد يوم واحد بالضبط.
  - `resume.spec.js` — الاستئناف بعد إغلاق المتصفح فعليًا عند مراحل مختلفة.
  - `backup-cycle.spec.js` — دورة تصدير→ضبط→استيراد حقيقية عبر تنزيل/رفع ملف.
  - `offline.spec.js` — عمل التطبيق كاملًا في وضع الطيران بعد أول زيارة.
  - `sw-update.spec.js` — مسار ترقية Service Worker: نسخة جديدة ← إشعار ← تفعيل.
  - `accessibility.spec.js` — فحص آلي بـ axe-core لعدم وجود مخالفات WCAG 2.1 AA
    عبر كل شاشة وحالة رئيسية.
  - `confirmations.spec.js` — سؤال التأكيد: التراجع بالزرّ وبـEscape لا يترك
    أثرًا، والتأكيد ينفّذ، وعدّادات المراحل تبقى بلا نافذة.
  - `performance-budget.spec.js` — إجمالي أول تحميل للوحة اليوم أقل من 200
    كيلوبايت (عدا الخطوط وصور الخرائط الكسولة).

## الوصولية والأداء

- تباين ألوان AA (4.5:1 للنص، 3:1 لحدود عناصر الواجهة) في السمتين الفاتحة
  والداكنة — لكل لون تمييز صيغتان في الطبقة الدلالية: `--accent` للتعبئة
  المصمتة و`--accent-text` للنصّ عليها (وكذلك `--ornament` و`--danger`)، لأن
  اللون الصالح خلفيةً لا يبلغ بالضرورة 4.5:1 نصًّا فوق الورق.
- الحركة إزاحةٌ بلا تعتيم: التعتيم يخفض التباين الفعلي طوال مدّته، وهي مدّة
  يقرأ فيها المستخدم فعلًا.
- مساحات لمس ≥ 44×44px، مؤشرات تركيز مرئية على كل عنصر تفاعلي، `aria-live`
  للعدّادات، ودعم `prefers-reduced-motion`.
- لا اعتماد على اللون وحده لنقل المعنى؛ كل حالة مصحوبة بنص.
- الأفعال المؤثّرة (إنهاء الجلسة، نتيجة المراجعة، إعادة توزيع المتراكم، إلغاء
  الهدف، التصدير) تمرّ بنافذة تأكيد أصلية `<dialog>` — حبس التركيز وEscape من
  المتصفح نفسه، والتركيز الافتراضي على «رجوع». أما عدّادات المراحل فبلا تأكيد
  عمدًا: تُضغط عشرات المرات في الجلسة الواحدة.
